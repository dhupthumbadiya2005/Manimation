# Phase 1 build spec — Coder + Render + Retry loop

## Goal

Build a pipeline that takes a single hand-written scene description (JSON, provided by us, not generated by any AI yet) and reliably produces a rendered Manim video clip for that scene, using an LLM to write the code and an automatic retry loop to fix errors. No planner, no RAG, no critic, no UI in this phase. This is the core engine everything else plugs into later.

## Environment

- Python 3.10+
- Manim Community Edition, pinned version — check what's installed and pin it in `requirements.txt`. Do not assume ManimGL or old `manim-cairo` syntax; this must be Community Edition only.
- LaTeX distribution available for `MathTex`/`Tex` (needed for later phases even if not exercised in the 5 test scenes — verify it's installed now).
- LLM access via API (Anthropic Claude — use whatever SDK/key is configured in this environment).
- ffmpeg installed (not used for concatenation yet, but confirm it's available).

## Folder structure

```
project/
  scenes/                 # hand-written input JSON files (5 of them for testing)
    scene_01.json
    scene_02.json
    ...
  runs/
    <run_id>/
      scene_<n>/
        attempt_1.py
        attempt_1_stdout.log
        attempt_1_stderr.log
        attempt_2.py
        ...
        final.mp4          # only if a successful attempt exists
        result.json         # summary: success/fail, attempts used, final error if any
  src/
    coder.py               # LLM call: scene JSON -> Python code
    renderer.py             # subprocess execution of Manim, capturing output
    retry_loop.py            # orchestrates coder -> render -> on failure, retry
    lint.py                  # cheap pre-render static checks (see below)
    main.py                   # CLI entrypoint
  requirements.txt
```

Every attempt's code and logs must be persisted to disk, never overwritten or discarded, even on success. We need to be able to inspect any past run without re-executing it.

## Input format (5 hand-written test files)

Write 5 files under `scenes/` by hand, in this schema, before writing any pipeline code — they are the fixture data for this phase:

```json
{
  "scene_id": 1,
  "goal": "one sentence describing what this scene should show",
  "mobjects": [
    {"id": "title", "type": "Text", "content": "Binary Search", "cell": "top-center"},
    {"id": "arr", "type": "VGroup", "content": "array of 10 numbered boxes", "cell": "mid-center"}
  ],
  "beats": [
    {"action": "FadeIn", "target": "title", "duration": 0.8, "note": "show title"},
    {"action": "Create", "target": "arr", "duration": 1.5, "note": "draw the array"}
  ],
  "max_simultaneous_mobjects": 4
}
```

Grid cells available (fixed, do not deviate): `top-left, top-center, top-right, mid-left, mid-center, mid-right, bot-left, bot-center, bot-right, full`. Include the pixel/unit mapping for these cells as a constant in `coder.py` — do not let the LLM invent coordinates.

Vary the 5 scenes in complexity: one trivial (title card only), one text/equation-based, one with a simple data structure (array or tree), one with 3+ mobjects to stress the max-simultaneous rule, one that will plausibly need a fix on first attempt (deliberately ambiguous mobject type, to test the retry loop actually gets exercised).

## `coder.py` — LLM call

- Input: one scene JSON object (as above), plus a fixed system prompt.
- Output: a single complete Python file, one `Scene` subclass, class name derived from `scene_id` (e.g. `Scene1`).
- System prompt must state explicitly, as hard rules:
  - Manim Community Edition syntax only, target the pinned version.
  - Frame is 14.2 units wide × 8 units tall; use the provided grid-to-coordinate mapping, never invent absolute coordinates.
  - Scene must start from an empty frame and end with everything faded out (`FadeOut` all mobjects as the last beat, even if not explicitly listed in `beats`).
  - Never exceed `max_simultaneous_mobjects` on screen at once.
  - Output ONLY the Python code, no prose, no markdown code fences.
- On retry (see below), the same call is reused but with the error and previous code appended to the prompt, asking for a complete rewritten file — not a diff, not a patch. Always regenerate the whole file.

## `lint.py` — pre-render static checks (no LLM, run before every render attempt)

Reject and immediately fail (skip straight to retry) if any of:
- No `Scene` subclass found, or more than one.
- Contains `while` loops.
- Contains `time.sleep`.
- Imports outside an allowlist (`manim`, `numpy`, `math` — nothing else).
- Contains negative or unusually large literal coordinates passed to `move_to`/`shift` (basic regex heuristic is fine here, doesn't need to be exhaustive).

This step must be fast and run before spending time on a render. Log why a lint check failed the same way a render failure is logged.

## `renderer.py` — execution

- Run the generated file via Manim CLI in a subprocess: `manim -ql <file> <SceneClassName>`.
- Enforce a wall-clock timeout (90 seconds) — kill the process and treat as a failure (with stderr noting "timeout") if exceeded.
- Enforce no network access for the subprocess if the environment allows sandboxing this.
- Capture stdout and stderr fully to the attempt's log files regardless of success or failure.
- On success, copy the rendered mp4 to `runs/<run_id>/scene_<n>/final.mp4`.

## `retry_loop.py` — orchestration

```
for attempt in 1..3:
    code = coder.generate(scene, previous_error=last_error, previous_code=last_code)
    save attempt_<n>.py
    lint_result = lint.check(code)
    if lint_result.failed:
        last_error = lint_result.message
        continue
    render_result = renderer.run(code)
    save stdout/stderr logs
    if render_result.success:
        save final.mp4, write result.json {"success": true, "attempts": attempt}
        return success
    last_error = render_result.stderr
write result.json {"success": false, "attempts": 3, "final_error": last_error}
return failure
```

Cap at 3 attempts total (lint failures and render failures share the same counter — don't give lint failures free retries on top of the 3).

## `main.py` — CLI

```
python main.py --scene scenes/scene_01.json --run-id test1
```

Runs the full loop for one scene file and prints success/failure with the path to the result.

## Acceptance criteria for this phase

- All 5 hand-written scenes produce a `final.mp4` within 3 attempts, on at least 4 out of 5 runs when re-run from scratch (some LLM variance is expected — don't require 5/5 every time, but it should not be flaky below that).
- Every attempt, successful or not, leaves a complete code file and logs on disk.
- The deliberately-ambiguous test scene actually exercises the retry loop at least once (confirms the loop logic is real, not just passing on attempt 1 every time).
- No scene render exceeds the 90-second timeout under normal operation.

## Explicitly out of scope for this phase

Do not build: a planner, any RAG/pattern retrieval, a vision critic, multi-scene concatenation, or any user-facing interface beyond the CLI above. If any of these feel necessary to make Phase 1 work, stop and flag it rather than building it — it likely means the scene JSON fixtures need adjusting instead.
